# 乱序执行

## 描述

乱序执行（Out-of-Order）：**按操作数就绪顺序执行，而非程序顺序**。前面的指令卡在等内存，后面不依赖它的指令先算。P6 微架构把它带进 x86，被广泛认为是现代 x86 高性能 CPU 的**范式起点**；其首席设计师 David Papworth 因这项工作获得了 2022 年 ACM 突破奖。

## 核心内容

- **P6 的核心设计哲学**：将复杂的 x86 指令**动态翻译为 RISC 风格的微操作（micro-operations）**，然后在硬件层面进行分析、重排序和重命名，以发现可并行执行的操作（见 [[现代Intel微架构]]）。
- Papworth 本人把 P6 的核心创新概括为 **「数据流处理」**：「寄存器重命名、乱序执行、宽超标量、深度流水线——这些特性让硬件能够利用底层应用中的并行性，而不受 x86 指令集人为约束的影响。」
- **乱序执行、顺序提交**：指令可以乱序算，但结果要按程序顺序「退休」（retire），通过退休单元保证架构状态一致——外面看起来永远像是一条一条按顺序执行的。
- （补充）**它离不开两个搭档**：没有 [[寄存器重命名]]，假依赖（两条指令只是碰巧用了同一个寄存器名）会把乱序的空间堵死；没有 [[推测执行]]，遇到分支就得停下来等，乱序窗口里永远装不满指令。
- （补充）**思想比 P6 早得多**：1967 年 IBM System/360 Model 91 的浮点单元用 Tomasulo 算法（保留站 + 公共数据总线）做了乱序执行；P6 的贡献是把它连同重排序缓冲（ROB）做进一颗面向大众的 x86 芯片。

## 例子

- （补充）`load r1, [mem]`（缓存未命中，要等 ~100 个周期）后面跟着十几条与 r1 无关的算术指令：按序 CPU 全部干等；乱序 CPU 先把这些算术指令做完，等 load 回来时它们已经在 ROB 里排队等退休了。

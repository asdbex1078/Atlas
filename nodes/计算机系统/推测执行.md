# 推测执行

## 描述

推测执行（Speculative Execution）：**预测分支方向并提前执行，通过「退休单元」保证架构状态一致性**。程序里大约每 5～7 条指令就有一个分支，如果每次都等分支条件算出来再取指，[[指令流水线]] 和 [[乱序执行]] 窗口都会频繁断流。

## 核心内容

- **P6 引入的关键技术之一**，与乱序执行、[[寄存器重命名]] 一起构成「动态执行」。
- （补充）**怎么回滚**：推测出来的结果只写进重排序缓冲（ROB）和物理寄存器，不写架构状态；分支确认猜错，就把这之后的所有指令作废、恢复寄存器映射。猜对了，这些指令按顺序退休，像从来没「推测」过一样。
- （补充）**分支预测器决定它值不值**：现代预测器准确率在 95% 以上，流水线越深（见指令流水线里的 NetBurst），猜错一次的代价越大，预测器就越重要。
- （补充）**副作用**：架构状态能回滚，**缓存状态不回滚**。2018 年公开的 Spectre / Meltdown 正是利用这一点——推测执行期间读到的秘密数据在缓存里留下痕迹，再用计时侧信道把它读出来。此后操作系统加了 KPTI（内核页表隔离）等缓解措施，系统调用变贵了一截。

## 例子

- （补充）`if (i < len) x = arr[i];`：CPU 预测 `i < len` 成立，在比较结果出来前就去读 `arr[i]`；如果其实越界了，`x` 的赋值会被作废，但 `arr[i]` 所在的缓存行已经被加载——这就是 Spectre 变种 1 的形状。

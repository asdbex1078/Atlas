# x86-64

## 描述

x86-64 是 x86 从 32 位走到 64 位的那次扩展。（补充）它由 AMD 在 2003 年的 Opteron / Athlon 64 上首先实现（AMD64）；Intel 自己的 64 位路线 IA-64（Itanium）不兼容 x86 而失败，最终反过来采用了 AMD 的方案——原文所说的 **Intel 64 位扩展（EM64T）在 Prescott 核心的 Pentium 4E（2004）上首次实现**。

## 核心内容

**64 位模式（IA-32e Mode）的核心变化**（原文）：

- 8 个现有通用寄存器扩展到 **64 位**：RAX、RBX、RCX、RDX、RSI、RDI、RBP、RSP；
- 新增 **8 个 64 位通用寄存器**：R8～R15；
- 新增 **8 个 128 位 SSE 寄存器**：XMM8～XMM15；
- 指令指针从 EIP 扩展为 **64 位 RIP**；
- 新增 **REX 操作码前缀**，用于访问扩展寄存器和 64 位操作数。

**地址空间**：Prescott（P4）和 Nocona（Xeon）都是 **48 位**虚拟地址、**36 位**物理地址（64GB）。

**模式划分**：
- **Legacy Mode**：传统 16/32 位模式；
- **Compatibility Mode**：在 64 位 OS 下运行 32 位应用，虚拟地址空间限制为 4GB；
- **64-bit Mode**：应用重新编译后使用 64 位寻址和扩展寄存器。

64 位模式下，**段机制几乎被完全架空**，默认使用**平坦地址空间**（单一代码、数据、栈空间）——[[保护模式]] 留下的只有特权级那套门禁；[[分页]] 在 64 位模式下必须开启（四级页表）。

- （补充）**为什么多出来的寄存器很重要**：32 位 x86 只有 8 个通用寄存器，函数参数只能走栈；x86-64 的 System V 调用约定前 6 个整数参数走 RDI、RSI、RDX、RCX、R8、R9，少了大量访存。

## 例子

- （补充）`mov rax, rbx` 的机器码是 `48 89 D8`：开头的 `48` 就是 REX 前缀（REX.W=1，表示 64 位操作数）；去掉它 `89 D8` 就是 32 位的 `mov eax, ebx`。

# 重定位

## 描述

编译时不知道共享库和可执行文件最终会加载到哪个地址，所以目标文件里对外部符号、绝对地址的引用只能先留空，同时在 `.rel.*` / `.rela.*` 节（见 [[ELF节]]）里写下「这个位置要按这种方式填上那个符号的地址」。静态链接时由[[链接器]]填，动态链接时由动态链接器在加载后填（见 [[动态链接]]）。

为了让这件事可行，需要四样东西配合：

- 位置无关代码（PIC）
- 全局偏移表（GOT）
- 过程链接表（PLT）
- 重定位表

## 核心内容

### x86-64 常见重定位类型

- `R_X86_64_64`：填 64 位绝对地址
- `R_X86_64_PC32`：填相对当前 PC 的 32 位偏移
- `R_X86_64_PLT32`：经 PLT 调用函数
- `R_X86_64_GOTPCREL`：PC 相对地访问 GOT 条目
- `R_X86_64_GLOB_DAT`：把数据符号地址填进 GOT
- `R_X86_64_JUMP_SLOT`：把函数地址填进 GOT.PLT（延迟绑定用）
- `R_X86_64_RELATIVE`：基址 + 加数，PIE/共享库自身的内部指针
- `R_X86_64_COPY`：把共享库里的数据拷到可执行文件
- `R_X86_64_TLS*`：线程局部存储

### 个人理解

`.o` 的 `e_type` 叫 `ET_REL`（可重定位目标文件），名字就说明了它的本质：一堆还没填地址的代码。`R_X86_64_RELATIVE` 是 PIE 之所以能随机基址（ASLR）的关键——加载器知道基址后，把所有内部指针统一加上去就行。

# 动态链接与 GOT/PLT

## 描述

共享库在运行时才确定加载地址，调用它里面的函数、访问它里面的变量，都要等加载后才知道地址。动态链接器（`/lib64/ld-linux-x86-64.so.2`，本身也是 ELF 共享对象）在 [[ELF加载过程]] 的最后阶段接手：解析 `.dynamic`、加载 `DT_NEEDED` 依赖、执行[[重定位]]、解析符号、跑初始化函数、跳进 `main`。

靠的是 [[ELF节]] 里这一组节：`.interp`、`.dynamic`、`.dynsym`、`.dynstr`、`.gnu.hash`、`.rela.dyn`、`.rela.plt`、`.got`/`.got.plt`、`.plt`。

## 核心内容

### GOT/PLT 调用过程

外部函数调用通常被编译成：

```asm
call func@plt
```

PLT 桩跳转到 GOT 中存的地址。首次调用时，GOT 条目可能指向 PLT 里的解析代码，由动态链接器解析出真实地址并写回 GOT；之后再调用就直接跳过去。

这就是**延迟绑定**（lazy binding）。可以用 `LD_BIND_NOW=1` 或链接选项 `-z now` 改成立即绑定。

### 符号版本

glibc 使用符号版本，比如：

```text
memcpy@GLIBC_2.14
```

同一个库可以导出同一符号的多个版本，保证旧程序照样能跑。相关节：`.gnu.version`、`.gnu.version_d`、`.gnu.version_r`。这和 SONAME、动态标签一起，是 Linux 长期二进制兼容（ABI 稳定性）的基础。

### 性能与 ABI（作者从数据库角度的总结）

- **PLT/GOT 开销**：外部函数调用多一次跳转。可用 `-fno-plt`、`-Bsymbolic`、`-fvisibility=hidden` 优化
- **延迟绑定**：首次调用较慢；`-z now` 行为可预测但启动稍慢
- **静态 vs 动态链接**：数据库核心常动态链接 libc、libssl、libaio、libnuma
- **符号冲突**：多个插件可能导出同名符号，需要隐藏内部符号
- **LD_PRELOAD**：可以 hook、审计、测试（CSAPP 里叫库打桩），生产上要谨慎

### 个人理解

「内核只负责加载解释器，复杂符号解析放在用户态」是一个很干净的分工：内核的 ELF 加载器保持简单，动态链接策略（延迟绑定、版本、预加载）全部可以在用户态演进。

## 例子

### 数据库 C 扩展加载（dlopen/dlsym）

数据库的「用 C 写扩展函数 / 插件」机制，底层全是 ELF 共享库 + 动态链接：扩展编成 `.so`，数据库进程运行时 `dlopen` 把它映射进自己的地址空间，再用 `dlsym` 在动态符号表里按名字找到入口函数。

#### PostgreSQL

```sql
CREATE FUNCTION add_one(integer) RETURNS integer
AS '$libdir/add_one', 'add_one'
LANGUAGE C STRICT;
```

```c
#include "postgres.h"
#include "fmgr.h"

PG_MODULE_MAGIC;

PG_FUNCTION_INFO_V1(add_one);

Datum
add_one(PG_FUNCTION_ARGS)
{
    int32 arg = PG_GETARG_INT32(0);
    PG_RETURN_INT32(arg + 1);
}
```

```sh
gcc -fPIC -shared -I$(pg_config --includedir-server) -o add_one.so add_one.c
```

PostgreSQL 服务器通过 `dlopen` 加载 `.so`，通过 `dlsym` 找到 `add_one`。`PG_MODULE_MAGIC` 用于 ABI 校验。

#### MySQL / SQLite

```sql
INSTALL PLUGIN myplugin SONAME 'myplugin.so';
```

```sql
SELECT load_extension('./myext.so');
```

这些机制都依赖 ELF 动态库、动态符号表、重定位和 ABI。

#### 要注意的点

- **插件 ABI**：扩展必须匹配服务器 ABI、glibc 版本、C++ ABI
- **符号冲突**：多个插件可能导出同名符号，要 `-fvisibility=hidden` 隐藏内部符号
- **安全**：插件是任意代码，必须信任；RELRO、ASLR、NX 只能降低风险

#### 旁支：数据库 JIT 与 eBPF 观测

- 数据库表达式 JIT 常用 LLVM 生成 ELF 目标文件、运行时加载（PostgreSQL JIT、ClickHouse、部分商业数据库）
- eBPF 程序编译为 ELF 对象，libbpf 加载进内核，可用来观测数据库的 I/O、锁、调度、网络

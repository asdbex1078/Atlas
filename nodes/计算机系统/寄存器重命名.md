# 寄存器重命名

## 描述

寄存器重命名（Register Renaming）：**消除虚假数据依赖（WAR/WAW），暴露真正的并行性**。x86 只有 8 个通用 [[寄存器]]（64 位也才 16 个），编译器不得不反复复用同一个寄存器名，于是大量指令之间出现「只是名字相同、数据并不相关」的依赖。CPU 内部准备远多于此的物理寄存器，每次写寄存器都分配一个新的物理寄存器，名字上的冲突就消失了。

## 核心内容

- **三种数据依赖**：（补充）
  - RAW（写后读）——真依赖，后一条确实要用前一条的结果，只能等；
  - WAR（读后写）、WAW（写后写）——假依赖，只是用了同一个寄存器名；重命名把它们消掉。
- **P6 引入的关键技术之一**，与 [[乱序执行]]、[[推测执行]] 一起构成 P6 的「动态执行」。
- （补充）实现上是一张**寄存器别名表（RAT）**：架构寄存器 → 当前对应的物理寄存器；指令退休时旧的物理寄存器才回收。推测执行猜错时，把 RAT 恢复到分支点的快照即可回滚。

## 例子

- （补充）
  ```
  mov eax, [a]    ; ①
  add ebx, eax    ; ② 依赖 ①（RAW，真依赖）
  mov eax, [b]    ; ③ 和 ② 是 WAR：② 还没读完 eax，③ 不能写
  add ecx, eax    ; ④ 依赖 ③
  ```
  重命名后 ① 写 P1、③ 写 P7，①② 和 ③④ 变成两条互不相关的链，可以并行。

# 指令流水线

## 描述

流水线让 CPU 在同一时刻处理好几条指令的不同阶段：第 1 条在执行时，第 2 条在译码，第 3 条在取指。理想情况下每个时钟周期完成一条指令，而不是每条指令要等前一条全部做完。

## 核心内容

- **80486（1989）**把流水线带进 x86 主流（原文时间线：「集成 FPU，L1 缓存，流水线」）。
- **超流水线（Superpipelining）**：P6 从 Pentium 的 **5 级**流水线扩展到 **14 级**——每一级做的事更少，时钟就能更快。
- （补充）**级数不是越多越好**：分支预测一旦猜错，流水线里已经装进去的错误指令全部要清掉，级数越深清掉的越多。NetBurst（Pentium 4）把流水线拉到 20 级、Prescott 拉到 31 级去冲主频，结果功耗失控、性能不升反降，Intel 随后回到 P6 路线做 Core 2——这是流水线深度最有名的反面教材。
- （补充）**三类冒险**：结构冒险（两条指令抢同一个部件）、数据冒险（后一条要用前一条还没算出来的结果）、控制冒险（分支还没算出来该取哪条）。转发（bypass）、[[寄存器重命名]]、分支预测 / [[推测执行]] 分别是对付它们的办法。

## 例子

- （补充）教科书 MIPS 五级流水线：IF（取指）→ ID（译码 / 读寄存器）→ EX（执行）→ MEM（访存）→ WB（写回）。`add r1, r2, r3` 紧跟 `sub r4, r1, r5` 时，sub 在 ID 阶段要读 r1，而 add 要到 WB 才写回——不加转发就得停两拍。

# 保护模式

## 描述

保护模式是 x86 从「所有程序运行在上帝权限下」走向「操作系统管得住程序」的那一步。**80286（1982）首次引入，80386（1985）把它做成了真正能用的样子。**

## 核心内容

- **286 的雏形**：首次引入保护模式，引入了**选择子（Selector）**和**描述符表（GDT/LDT）**的概念，**Ring 0-3 特权级也从这一代开始**。但段长被限制在 64KB，导致实际应用中并不流行。
- **386 的完善**：首次支持 32 位线性地址（IA32），段可以覆盖整个 4GB，于是可以做**平坦寻址（flat addressing）**——所有段基址设成 0、段长设成 4GB，段机制形同虚设，x86 由此「能够运行 Unix」。386 同时加了**分页**（见 [[分页]]），从此真正的隔离靠页表而不是段。
- **Virtual-8086 模式（V86）**：386 新增，在保护模式操作系统下透明地虚拟化实模式环境，通过 EFLAGS 寄存器中的 VM 位启用——这就是 Windows 3.x / 95 里还能跑 DOS 程序的原因。
- （补充）**选择子是怎么用的**：保护模式下段寄存器里放的不再是「段基址 ÷ 16」，而是一个 16 位选择子：高 13 位是描述符表里的下标，TI 位选 GDT 还是 LDT，低 2 位是请求特权级（RPL）。CPU 拿下标去表里取出 8 字节的段描述符，里面才是真正的基址、段长和访问权限（DPL）。每次访问都要比较当前特权级（CPL）、RPL 和 DPL，越权就触发通用保护异常（#GP）。
- （补充）**为什么要特权级**：没有它，用户程序可以直接改页表、关中断、写别人的内存。Ring 0 给内核、Ring 3 给用户程序（Ring 1/2 几乎没人用）；系统调用就是从 Ring 3 合法地进入 Ring 0 的那扇门（`int 0x80` / `sysenter` / `syscall`）。
- **64 位模式下段机制几乎被完全架空**，默认使用平坦地址空间——保护模式留下来的真正遗产是特权级和描述符表这套「门禁」，而不是分段本身（见 [[x86-64]]）。

## 例子

- （补充）Linux 0.11 进程切换时，靠 GDT 里每个进程的 TSS 描述符和 LDT 描述符完成——这正是你笔记里「进程切换需要保存上下文到 tss、查询 GDT 表」的那件事；后来的 Linux 不再用硬件任务切换（TSS 只留一个、存内核栈指针），上下文改由内核自己在 `switch_to` 里保存。
- （补充）用户程序执行 `cli`（关中断）会触发 #GP：它在 Ring 3，而 `cli` 要求 CPL ≤ IOPL。

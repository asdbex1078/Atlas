# DeepSeek开源模型迭代史：从LLM到V4的技术演进

## 前言

2024年初至今，DeepSeek在不到三年内完成了从初代通用模型到第四代旗舰的跨越。每一次迭代都伴随着架构层面的实质性创新，而非单纯的参数堆叠。本文将系统梳理DeepSeek开源模型的发展脉络，聚焦每个版本的发布时间、核心技术、论文链接、参数规模，以及它所解决的关键问题。


## 2024年1月：DeepSeek LLM——起点

**发布时间**：2024年1月5日

**参数量**：初代版本，参数规模未明确披露

**核心技术**：标准Transformer解码器架构，奠定了DeepSeek系列的技术路线基础

**解决的问题**：作为系列基石，验证了DeepSeek团队在大规模语言模型训练上的工程能力，为后续迭代提供了核心方法论

**论文**：初代技术报告未在搜索结果中提供具体链接


## 2024年5月：DeepSeek-V2——MoE架构的引入

**发布时间**：2024年5月

**参数量**：236B总参数，21B激活参数

**核心技术**：
- **混合专家（MoE）架构**：采用动态路由机制，每个token仅激活12%的专家模块，推理速度提升3.2倍
- **多头潜在注意力（MLA）**：通过低秩联合压缩KV缓存，显著降低推理时的内存带宽瓶颈

**解决的问题**：在保持模型容量的同时大幅降低推理成本，使236B参数的模型能在单机8卡部署

**论文**：搜索结果未提供V2技术报告的直接链接


## 2024年6月：DeepSeek-Coder-V2——代码能力的专项突破

**发布时间**：2024年6月

**参数量**：236B总参数，21B激活参数（Lite版本为16B总参数，2.4B激活）

**核心技术**：沿用DeepSeek-V2的MoE架构，针对代码场景专项优化，支持**FIM（Fill-in-the-Middle）补全**，上下文32K

**解决的问题**：在代码和数学能力上达到全球第二，介于GPT-4o和GPT-4-Turbo之间，同时保持通用能力

**论文**：https://github.com/deepseek-ai/DeepSeek-Coder-V2/blob/main/paper.pdf


## 2024年12月：DeepSeek-V3——架构创新的集大成者

**发布时间**：2024年12月26日

**参数量**：671B总参数，37B激活参数

**核心技术**：
- **MLA（多头潜在注意力）**：KV缓存压缩14倍，大幅降低推理内存占用
- **细粒度专家分割**：256个路由专家+共享专家，稀疏度显著提升
- **无辅助损失负载均衡**：通过动态调整偏置项而非辅助损失来平衡专家负载
- **FP8混合精度训练**：首个成功使用FP8训练的大规模MoE模型，训练成本仅约557万美元
- **多Token预测（MTP）**：训练时提供更多监督信号，推理时可结合投机采样加速

**解决的问题**：证明了极致稀疏的MoE架构可以在极低训练成本下达到顶尖性能。训练每万亿token仅需180K GPU小时，将“经济性”贯彻到底

**论文**：DeepSeek-V3 Technical Report, arXiv:2412.19437


## 2025年1月：DeepSeek-R1——推理能力的范式突破

**发布时间**：2025年1月20日

**参数量**：基于V3的671B MoE架构

**核心技术**：
- **纯强化学习训练推理能力**：R1-Zero完全不使用SFT，仅通过RL让模型自发涌现推理行为
- **多阶段训练+冷启动数据**：R1在R1-Zero基础上引入冷启动数据，解决可读性和语言混用问题
- **规则奖励机制**：使用准确性奖励和格式奖励，而非神经奖励模型，避免奖励劫持

**解决的问题**：首次证明大语言模型的推理能力可以通过**纯强化学习**来提升，大幅减少对人类标注数据的依赖。在数学基准测试中，R1-Zero和R1分别达到77.9%和79.8%

**论文**：DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning, arXiv:2501.12948；正式版发表于《Nature》


## 2025年5月-12月：V3.1 / V3.2——推理与通用的融合

**核心技术方向**：将R1的推理能力与V3的通用能力融合，统一“思考”与“非思考”模式。V3.2成为生产环境的基线版本，支持工具调用，而R1本身不支持原生工具调用

**解决的问题**：解决了“推理模型不能做Agent”的痛点，让同一个模型既能深度推理，又能调用工具完成复杂任务


## 2026年4月：DeepSeek-V4——百万上下文与架构大换代

**发布时间**：2026年4月24日

**参数量**：
- **V4-Pro**：1.6万亿总参数，49B激活参数
- **V4-Flash**：2840亿总参数，13B激活参数

**核心技术**：
- **CSA + HCA混合注意力架构**：压缩稀疏注意力（每4个token合并为1个压缩条目+闪电索引器筛选top-k）与重度压缩注意力（128倍压缩率）交替使用，百万token下KV缓存仅为V3.2的10%，计算量仅为27%
- **mHC（流形约束超连接）**：将残差映射矩阵约束在双随机矩阵流形上，解决深层堆叠的数值不稳定问题
- **Muon优化器**：替代AdamW，对梯度矩阵做近似正交化，考虑参数矩阵整体结构信息
- **原生100万token上下文**：V4-Pro和V4-Flash均支持

**解决的问题**：在不牺牲性能的前提下，将上下文窗口扩展至百万token级别，同时将长文本推理成本降至可工程化落地的水平。解决了传统注意力机制下长上下文计算量平方级增长的瓶颈

**论文**：V4技术报告（58页），搜索结果未提供arXiv直接链接


## 技术演进主线

纵观DeepSeek的迭代路径，有三条清晰的主线：

**1. 注意力效率的持续优化**：从V2的MLA → V3的MLA+MoE稀疏化 → V4的CSA/HCA混合压缩。每一步都在解决“如何在更长上下文、更大参数下控制计算和内存成本”这一核心矛盾。

**2. 推理能力的独立与融合**：R1证明了纯RL可以训练出推理能力，V3.1/V3.2将这一能力融入通用模型，V4则在此基础上进一步强化Agent和复杂任务处理。

**3. 训练效率的极致追求**：V3以557万美元的训练成本对标GPT-4o，V4在百万token场景下将计算量降至前代的27%。DeepSeek的“经济性”路线贯穿始终。
